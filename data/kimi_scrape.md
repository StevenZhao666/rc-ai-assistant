### 1. 现有措施：哪些有效

**60/min + 429** 对简单爬虫和突发过载有效，单进程用内存计数也够用；但重启会清零、换 IP 可绕过，而且 Apache 直出的 `/ai/files/` 完全不受应用限流约束。  
**limit 封顶**能防单次大响应，**邮箱默认不公开**能减少隐私泄露，但都阻止不了分页、逐条采完。  
`X-Robots-Tag` 和 `meta noindex` 只影响守规矩搜索引擎的索引，**不算反扒**；公开且无需登录的内容无法真正禁止复制，现实目标是保可用性、提高批量成本。

### 2. 最值得补的 3 件事

- **先堵文件旁路**：中小文件改走 `/api/files/{id}/download`，按 ID 查库后用 `FileResponse` 流式返回，使用独立下载桶和全局并发，禁止拼接用户路径；大文件必须静态直出时，可在 Apache 用 `mod_evasive` 做宽松、约 30 秒的突发短封兜底，别把 UA/Referer 检查当防线。
- **缓存并隔离贵接口**：公共 GET 200 加 `Cache-Control: public, max-age=60`，配合 Apache `mod_cache`（shmcb）缓存，排除 429、上传和个性化响应；`/api/search` 限制 `q` 长度、避免无索引全表 `LIKE`，单独从 `10–20/min/IP` 起步，并限制全局搜索并发为 1–2。
- **补观测再调阈值**：Apache 日志加 `%D` 记录耗时，定期看 Top IP、路径、状态码和 429；不要一开始就用 fail2ban 长封，否则很容易把正常校园出口一起封掉。

### 3. 邮箱：明确推荐

推荐**站内联系表单**，并把选项改成“允许通过本站联系我”，作者邮箱永不下发浏览器或 JSON。  
收件人只能由服务端根据作者 ID 查库，表单加 honeypot、最短填写时间、每 IP 与每作者限频，且不允许任意收件人或附件，避免变成垃圾邮件中继。  
单纯打码若无法联系就是功能残缺，若点击或接口能还原，爬虫同样能拿到；明文只在作者另行确认“可能被永久采集”后作为次选。

### 4. 会不会误伤正常学生

**会**：图书馆、教室 NAT 和运营商 CGNAT 都可能共享那 60 次；若 FastAPI 读到的还是 `127.0.0.1`，更会全站共用一个桶。  
先确认真实客户端 IP：`uvicorn ... --host 127.0.0.1 --proxy-headers --forwarded-allow-ips 127.0.0.1`，只信任本机 Apache 传来的代理头，应用端口不要暴露公网。  
普通读取可从令牌桶 `240/min + burst 60` 起步，搜索、下载使用独立桶，页面静态资源不计入 API 桶；触发后只短返 `429 + Retry-After`（约 15–30 秒），按日志调整，不做校园网段白名单或永久 IP 封禁。��库，会表现为"内容莫名变少"，要同步改分页；noindex 的真实代价是学生在 Google 搜不到你们规章——如果只是怕扒才加的，删掉。
