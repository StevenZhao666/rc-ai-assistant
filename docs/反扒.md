# 反扒措施（临时版）

目标不是“防住专业爬虫”，而是**别让公开页面被顺手抓走、别被搜索引擎索引、别让人一分钟刷几千次**。真要防全套，得上 WAF 和登录，那是后话。

## 现在做了四件

| 措施 | 做法 | 在哪 |
|---|---|---|
| 公开接口限速 | 每 IP 每分钟 60 次，超了 429 + `Retry-After` | `app/main.py` 的 `scrape_guard` 中间件 |
| 不让索引 | 所有响应带 `X-Robots-Tag: noindex, nofollow`；四个页面加 `<meta name="robots">` | 同上 + `app/static/*.html` |
| 单次取数封顶 | `limit` 参数上限 300（资料库）/ 50（搜索）/ 200（文件） | 各接口的 `Query(le=...)` |
| 邮箱默认不公开 | 只有作者勾「同意公開」才进公开接口 | `contact_public` 字段 |

限速只盖公开只读接口：`/api/library`、`/api/search`、`/api/files`、`/api/qa/`、`/api/clause`、`/api/updates`。

**不盖**：`/api/ask`（有自己的学号+IP 三级限额）、审核/后台（要身份）、静态文件（Apache 直出）。

## 调参

```bash
# 服务器 .env 里改，然后 systemctl restart rc-ai
SCRAPE_LIMIT_PER_MIN=60
```

60 是拍的。正常人翻资料库一分钟不会超过 10 次；写脚本抓全量，一分钟几百次。

## 已知挡不住

- **换 IP**：代理池、云函数，一分钟换一个 IP，限速就废了
- **慢速爬**：一分钟 50 次、爬一天，不触发任何限制
- **直接扒静态文件**：`/ai/files/...` 的 PDF 是 Apache 直出的，没有经过应用的限速

前两个要 WAF/人机验证；第三个要么把文件也过应用层（慢），要么给文件加签名 URL（改动大）。
