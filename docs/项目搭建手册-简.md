# 项目搭建手册（简体）

> 读者：拿到仓库、对这个项目一无所知的人。
> 目标：在本机从零跑通 → 跑测试 → 部署到一台 Linux 服务器。
> 基线：Windows 11 + Python 3.14.7 + uvicorn 0.54.0 + mcp 2.3.0，2026-11 实测。
> 文中所有标「实测」的输出，都是照本文命令真跑出来的，不是推测。带 `<尖括号>` 的地方要换成你自己的值。

---

## 0. 读前须知

### 0.1 你会得到什么

这是一个书院问答系统，能同时提供四样东西：

| 部件 | 地址 | 干什么 |
|---|---|---|
| 学生端问答 | `/` | 学生提问，答案带编号引用，答不上来转人工 |
| 资料库 | `/library` | 浏览已上架的院生作品、链接、文档 |
| 投稿页 | `/upload` | 学生用邀请码投文件，进候选队列 |
| 审批后台 | `/review`、`/admin` | 审核条目、抓取官网、看缺口与用量 |

再加两套只读接口：普通 HTTP JSON（`/api/search` 等）和 MCP（`/ai/mcp`、`/ai/mcp-files`），给 ChatGPT 类客户端、Cursor、Claude Desktop 用。

技术上刻意做小：FastAPI + SQLite + 中文二元组 BM25，不用向量库，不用前端构建，单进程就能跑，2 核 4G 的机器够用。

### 0.2 你需要什么基础

- 会在 cmd 里 `cd` 到目录、会用记事本或 VS Code 改文本文件。
- 不需要懂前端、不需要懂 BM25、不需要 GPU。
- 想要「模型生成答案」需要一个 OpenAI 兼容接口的 key（DeepSeek、智谱、校内网关都行）。没有 key 也能跑，只是回答退化成「摘录原文」，功能链路完全一样。

### 0.3 全程要多久

| 阶段 | 时间 |
|---|---|
| 装 Python / git / 建 venv / 装依赖 | 10–20 分钟（看网速） |
| 配置 + 造示例数据 + 起服务 | 10 分钟 |
| 跑一遍测试 | 5 分钟（`test_scrape` 会占一分钟） |
| 第一次部署到服务器（含 systemd、Apache） | 40–60 分钟 |

### 0.4 五步路线

```
第 1 步 装 Python / git          → 第 2 步 venv + 依赖 + .env
        ↓
第 3 步 造数据（示例或自己的资料）
        ↓
第 4 步 uvicorn 起来，/health 通，check.bat 全绿
        ↓
第 5 步 部署：deploy.py + 三个 systemd 单元 + Apache 反代
```

### 0.5 三条约定

1. 命令默认在 **cmd** 里执行（读者用 Windows）。bash / PowerShell 的写法差异会单独标出来。行尾的 `^` 是 cmd 的续行符，PowerShell 用反引号，bash 用 `\`。
2. `.env` 永远不进 git（`.gitignore` 已排除）。本文出现的 key、邀请码、学号全是占位符。
3. 书院名写作 **張崑崙書院**、吉祥物写作 **崑崑**（繁体）。这是正式文案的写法，代码里可能会出现别的简体字形，改文案时别顺手「简化」回去，也别写成「昆明」。

## 1. 环境准备

### 1.1 Python

要求 3.11 或更高。本项目在 **3.14.7** 上完整跑过（`python --version` 实测输出 `Python 3.14.7`）；3.11 / 3.12 是 `README` 与 `docs/DSH-接入.md` 写的门槛，依赖里 `mcp>=2.3` 也要求 3.10 以上。

安装建议：

- 从 python.org 下安装包，安装时勾 **Add python.exe to PATH**。
- 不要用 Microsoft Store 版：它装的是「应用执行别名」，`python` 会弹商店，`where python` 指向 `WindowsApps` 下的零字节占位文件。已经装了的话，用 `py -3.11` 启动，或卸载重装。

检查：

```bat
python --version
py -0p
```

期望：第一行是 `Python 3.11.x` 以上；第二行列出本机所有解释器及路径。看不到 `py` 说明没装启动器，直接用 `python` 也行。

### 1.2 git

```bat
git --version
```

期望 `git version 2.x`。没有就去 git-scm.com 装，默认选项即可。

### 1.3 三个 Windows 坑

**坑一：cmd 换盘符要 `cd /d`。** 在 `C:\` 下执行 `cd D:\Projects` 不会有任何变化，也不报错。正确写法：

```bat
cd /d D:\Projects
```

**坑二：PowerShell 激活 venv 报「禁止运行脚本」。** 报错大意是 `无法加载文件 ...\Activate.ps1，因为在此系统上禁止运行脚本`。两个办法：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

或者干脆不激活：所有命令都用 `.venv\Scripts\python.exe` 全路径调用。本文统一用后者，因为它在 cmd / PowerShell / 计划任务里都成立。

**坑三：端口被占。** 起服务时报 `[Errno 10048] error while attempting to bind on address ('0.0.0.0', 8001)`：

```bat
netstat -ano | findstr :8001
taskkill /F /PID <上面查到的PID>
```

### 1.4 端口规划

| 端口 | 谁在用 | 备注 |
|---|---|---|
| 8001 | 本机 uvicorn | 开发默认 |
| 8091 | 服务器主服务 | Apache 反代到 `/ai/` |
| 8092 | 服务器 `cklc` MCP | 反代到 `/ai/mcp` |
| 8093 | 服务器 `cklc-files` MCP | 反代到 `/ai/mcp-files` |

## 3. 配置逐项解释

### 3.1 最小可用配置

`.env` 里填这五行就能跑：

```ini
LLM_BASE=https://api.deepseek.com/v1
LLM_KEY=sk-你的key
LLM_MODEL=deepseek-chat
REVIEWERS=uc00001
UPLOAD_CODE=改成只有你知道的口令
```

`LLM_KEY` 留空也能跑：`/health` 会显示 `"model":"extractive"`，回答只从检索到的条目里摘原文，不调模型。

### 3.2 模型与供应商链

代码里有一条链：主模型 → 同家备用模型 → 另一家兜底。任何一环成功就返回，全挂才退回摘录式。

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `LLM_BASE` | 与 KEY 同时填 | 空 | OpenAI 兼容接口根地址，末尾斜杠会被去掉 |
| `LLM_KEY` | 与 BASE 同时填 | 空 | 两者缺一，整条主链不启用 |
| `LLM_MODEL` | 建议显式写 | `qwen3.8-27b` | 主模型名 |
| `LLM_FALLBACK_MODELS` | 否 | 空 | 同家备用，逗号分隔，如 `glm-4.5-flash,glm-4-flash-250414` |
| `LLM_FALLBACK_BASE` | 否 | 空 | 换一家兜底，三项都填才生效 |
| `LLM_FALLBACK_KEY` | 否 | 空 | 同上 |
| `LLM_FALLBACK_MODEL` | 否 | 空 | 同上 |
| `LLM_CONCURRENCY` | 否 | `1` | 主供应商并发上限，1 = 本地排队串行；0 = 不限 |
| `LLM_QUEUE_WAIT` | 否 | `4` | 本地排队总预算（秒），不是每个模型各等一次 |
| `LLM_TIMEOUT` | 否 | `45` | 单请求硬上限（秒），防免费档挂死拖线程 |
| `LLM_THINKING` | 否 | `off` | `on`/`1` 打开思考；推理型模型开着容易把短答截成空串 |
| `LLM_DAILY_TOKENS` | 否 | `3000000` | 每天 token 上限，超了降级为原文摘录；读 `data/llm_usage.jsonl` 统计 |

免费档的关键经验：智谱免费档**超并发不排队**，直接回 429；所以 `LLM_CONCURRENCY=1` 是必需的自保，排不上队就落下一环。

### 3.3 身份与审核

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `REVIEWERS` | 上线必填 | 空 | 逗号分隔的审核人学号/姓名。**空 = 不校验**，谁打开 `/review` 都能点通过（仅本地开发） |
| `ADMINS` | 否 | 空 | 能看 `/admin` 数据看板、能看完整学号；空 = 与 `REVIEWERS` 相同 |

审核请求要带 `X-Reviewer` 头，值必须在 `REVIEWERS` 里，否则 401/403。

### 3.4 投稿

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `UPLOAD_CODE` | 要开投稿就必填 | 空 | **空 = 关闭投稿**，`POST /api/upload` 直接 503「投稿暂未开放」 |
| `UPLOAD_MAX_MB` | 否 | `20` | 单文件上限，超了 413 |
| `UPLOAD_MAX_FILES` | 否 | `3` | 一次最多几个文件 |

### 3.5 反扒与限额

这两组变量由 `app/main.py` 读，`.env.example` 里没有，要自己加。

| 变量 | 默认 | 说明 |
|---|---|---|
| `SCRAPE_LIMIT_PER_MIN` | `60` | 每个 IP 每分钟补充的令牌数 |
| `SCRAPE_BURST` | `20` | 一次最多攒多少令牌（瞬时并发） |
| `SCRAPE_BYPASS` | 空 | 内部脚本令牌；请求头 `X-Scrape-Token` 与它相等就跳过限速 |
| `ASK_LIMIT_PER_HOUR` | `10` | 每人每小时「走模型」的次数 |
| `ASK_BASIC_LIMIT_PER_HOUR` | `20` | 每人每小时「只摘原文」的次数 |
| `ASK_IP_LIMIT_PER_HOUR` | `60` | 单 IP 每小时总闸门（防止一个出口被几十人共用时无限刷） |

限额的主键是「学号 + 设备号，取用量最大者」，IP 只做总闸门。占位学号 `UC000000` 格式合法，但已被 `norm_sid()` 排除，否则所有匿名用户会被算成同一个人，几分钟就把额度用光。

### 3.6 检索与其他

| 变量 | 默认 | 说明 |
|---|---|---|
| `MIN_SCORE` | `2.5` | BM25 分数低于它就走兜底卡片，不硬答 |
| `ACADEMIC_YEAR` | `2026/27` | B 类（每年变）答案会加这个前缀 |
| `COLLEGE_NAME` | `張崑崙书院（CKLC）` | 出现在自我介绍、页面标题 |
| `OFFICE_ROOM` / `OFFICE_PHONE` / `OFFICE_EMAIL` | G003 / 8822 9520 / cklcollege@um.edu.mo | 兜底话术里的联系方式 |
| `DATA_DIR` | 项目下 `data` | 换库位置；改成别的目录可以做到「代码一份、数据多份」 |

### 3.7 `.env` 的解析规则（踩过才知道）

`app/config.py` 里是一个三十行的极简读取器，规则很死：

1. 只认 `KEY=VALUE` 整行；空行、行首 `#` 跳过。
2. **不剥引号**。写 `LLM_KEY="sk-abc"`，引号会成为 key 的一部分，模型返回 401。
3. 已有的系统环境变量优先（用的是 `os.environ.setdefault`）。系统里设过同名变量，改 `.env` 不生效。
4. 按 UTF-8 读。用记事本保存要选 UTF-8，选 ANSI 会把中文联系方式写坏。
5. 值两端的空格会被 strip，中间的空格保留。
6. 改完 `.env` 必须重启 uvicorn，代码不会热读。

### 3.8 泄露风险

| 泄露什么 | 后果 |
|---|---|
| `LLM_KEY` | 别人拿你的额度刷；按 token 计费的话直接是钱 |
| `SCRAPE_BYPASS` | 反扒形同虚设：带上 `X-Scrape-Token` 就能无限刷公开接口 |
| `REVIEWERS` 留空上线 | 任何人打开 `/review` 都能把草稿批成已发布，等于内容无人负责 |
| `UPLOAD_CODE` 太简单 | 被当免费网盘；虽然没有执行风险，但会塞满磁盘 |

`.gitignore` 已经排除 `.env`、`data/*.sqlite3`、`data/*.jsonl`、`data/files/`。提交前用 `git status` 扫一眼，别把 `.env` 带上去。

## 4. 初始化数据

### 4.1 库是自动建的

不需要手动建库。uvicorn 启动时执行 `db.init_db()`：建表、给老库补列、回填 `uid`、必要时回灌 FTS。实测空库第一次启动后是 **17 张表**（含 5 张 FTS5 影子表）。

表里最重要的四张：

| 表 | 内容 |
|---|---|
| `kb_item` | 问答条目（问题/答案/状态/时效类型/版本字段） |
| `chunk` | 规章条款原文（按条款或段落切） |
| `library_item` | 资料库作品/链接/文档 |
| `candidate` | 投稿与抓取候选（审核前的暂存区） |

### 4.2 造一份示例库

```bat
.venv\Scripts\python.exe scripts\seed_demo.py
```

实测输出：

```
新增 6 条，库里共 6 条（都是虚构示例）
```

再跑一次：

```
新增 0 条，库里共 6 条（都是虚构示例）
```

它按问题去重，重复跑不会灌两遍。六条都是 `published`，覆盖 A（长期稳定）、B（年度型）、C（实时活动）三种时效，够把 `/`、`/library`、`/review` 都点一遍。想验证「审核是硬约束」，把某条改成 `draft`，学生端立刻搜不到。

### 4.3 导入自己的 Excel（正式题库）

```bat
.venv\Scripts\python.exe scripts\build_kb.py "D:\资料\题库.xlsx"
```

- 两列：`问题`、`答案`，模板见 `docs/题库模板.md`。
- 这个脚本**没有 `--help`**：参数就是 xlsx 路径。传 `--help` 会被当成文件名，报 `InvalidFileException: openpyxl does not support  file format`。
- 加工规则放在 `data/overrides.py`（逐条修正）和 `data/source_map.py`（来源映射），从同目录的 `*.example.py` 复制后再改。每次重建都会重套一遍，所以修正是可重复的，不是手改数据库。
- 跑完看 `data/ingest_report.json` 里的警告项（空答案、往年、非官方、重复、模糊）。

### 4.4 导入 PDF / md / txt（规章原文）

```bat
mkdir inbox
.venv\Scripts\python.exe scripts\ingest_docs.py inbox --dry-run
.venv\Scripts\python.exe scripts\ingest_docs.py inbox --version AY2026-2027
```

实测（一个 109 字、含 3 个条款号的 md 文件）：

```
预览：1 个文件，version=AY2026-2027
  sample-rules.md: 109 字 → 3 段（按条款）

合计 3 段（未写入）
```

正式导入会多一行 `FTS 索引已重建：3 条`，结尾是 `合计 3 段 已写入 chunk 表`。

切片规则：

| 文件长什么样 | 切法 | anchor |
|---|---|---|
| 有 `1.1`、`2.4.1` 这类条款号（≥3 条） | 按条款切 | `1.1` |
| 海报、通知、FAQ（没编号） | 按空行切，每段 ≤900 字 | `p01`、`p02` |
| 扫描件（没有文字层） | 跳过，打印「跳过（没有文字层）」 | — |

同一个 `source + version` 再导一次是**先删后插**，不会重复。

**两个实测坑：**

1. **导完 `chunk.uid` 是空的。** `ingest_docs.py` 的 INSERT 没写 `uid`，要等下一次启动（`db.init_db()` 的回填逻辑）才补上。实测：导入后 `uid=None`，跑一次 `init_db()` 后变成 `chunk-0004`、`chunk-0005`、`chunk-0006`。所以**导完条款请重启一次服务**，否则 MCP 和 API 的引用里 `uid` 会缺。
2. **重复导入会换 uid，也不写历史。** 先删后插意味着新行拿到新 id 和新 `chunk-uid`，`chunk_revision` 仍是 0（实测 3 条 chunk、0 条历史）。条款改版建议换 `--version`（新学年号），而不是同名覆盖，这样旧版还在库里可查。

### 4.5 数据落在哪

```bat
dir data
dir data\files
```

| 路径 | 内容 |
|---|---|
| `data\kb.sqlite3` | 主库（问答、条款、资料库、审批、日志都在里面） |
| `data\files\inbox\YYMM\` | 上传的文件，按 sha256 前 12 位命名，同内容只存一份 |
| `data\qa_log.jsonl` | 提问流水，append-only，统计未命中靠它 |
| `data\llm_usage.jsonl` | 每次模型调用的 token 用量，日预算读它 |

查条数：

```bat
.venv\Scripts\python.exe -c "import sqlite3;c=sqlite3.connect('data/kb.sqlite3');print(c.execute('select status,count(*) from kb_item group by status').fetchall())"
```

## 5. 本机跑起来

### 5.1 起服务

```bat
.venv\Scripts\python.exe -m uvicorn app.main:app --port 8001
```

- 开发时加 `--reload`，改 Python 文件自动重启。
- 要让同网段的手机或同事访问，加 `--host 0.0.0.0`。
- 前台起的话，关掉窗口服务就没了。要长期后台跑，用 `start_all.bat`（它会隐藏窗口起进程）、计划任务，或直接在服务器上交给 systemd。

**不要用 `run.bat`。** 它调 `scripts\ingest_xlsx.py`，而这个文件在仓库里不存在（实测 `ls scripts/ingest_xlsx.py` 报 `No such file or directory`），属于旧脚本。建库用 `build_kb.py`，起服务直接 uvicorn。

`scripts\start_all.bat` 也不是给新机器用的：它会清 8001 进程、备份库、起 uvicorn，**再起 cloudflared 隧道**并打印公网地址。机器上没装 cloudflared 的话这一步会失败。它适合作者那台机器。

## 6. 第一个问答与第一次投稿

### 6.1 发一个提问

中文请求体在 cmd 里直接写容易因代码页变问号，建议存成 UTF-8 文件再发。

```bat
chcp 65001
```

新建 `body.json`（记事本另存为 UTF-8）：

```json
{"question":"書院能不能養寵物？"}
```

```bat
curl -X POST http://127.0.0.1:8001/api/ask ^
  -H "Content-Type: application/json" ^
  -H "X-Student-Id: uc88888" ^
  --data-binary @body.json
```

实测返回（截断展示）：

```json
{
  "answer": "不能。出於健康和安全原因，未經書院院長特別許可，書院成員和非書院成員居民不得帶寵物進入書院 [1]。",
  "mode": "llm:glm-4.5-flash",
  "citations": [
    {"id": 9, "uid": "kb-0009", "revision": 1, "content_hash": "e945488f0fda",
     "question": "張崑崙書院允許寵物嗎？", "category": "书院规章/设施/校务",
     "score": 24.99, "ttl_type": "A", "source": "澳大住宿式書院管理規章（UMRC Management Rules）"}
  ],
  "user": "uc88888",
  "quota": {"llm_left": 9, "basic_left": 20}
}
```

怎么读这个返回：

| 字段 | 含义 |
|---|---|
| `answer` | 正文，`[n]` 已按返回的 `citations` 重编号；对不上的标记会被删掉 |
| `mode` | `llm:模型名` 说明真调了模型并告诉你用了链上哪一环；`fallback_*` 是兜底；`policy_*` 是越界话术；`chat` 是寒暄，不占额度 |
| `citations` | **只列模型真正引用的条目**，不是检索命中的全部；每条带 `uid` + `revision`，可追溯是哪一版 |
| `quota` | 剩余额度；`llm_left` 走模型，`basic_left` 只摘原文 |

身份只认 `X-Student-Id` 请求头，不传就是占位号 `UC000000`（已排除在额度主键外）。这只是防手滑，不是安全机制——改个号就绕过去了。

### 6.2 投稿一份文件

```bat
curl -X POST http://127.0.0.1:8001/api/upload ^
  -H "X-Forwarded-For: 10.0.0.9" ^
  -F "code=<UPLOAD_CODE>" ^
  -F "kind=work" ^
  -F "title=示例作品" ^
  -F "author=测试同学" ^
  -F "contact=test@example.com" ^
  -F "consent=1" ^
  -F "files=@D:\tmp\demo.md"
```

返回：

```json
{"ok": true, "id": 7, "files": [{"file_id": 5, "name": "demo.md", "size": 7,
  "mime": "text/markdown", "sha256": "…", "url": "/files/inbox/202611/ea67f39f2a70.md"}]}
```

`id` 是候选号（`candidate` 表），不是资料库编号。校验顺序（错在哪一步就返回对应状态码）：

1. `UPLOAD_CODE` 没配 → 503；填错 → 403
2. 没勾授权 `consent` → 400
3. 标题少于 2 字 → 400
4. `kind` 不在 `work` / `link` / `doc` → 400
5. 没填电邮或格式不对 → 400
6. 没有文件 → 400；超过 `UPLOAD_MAX_FILES` → 400
7. 同 IP 一小时超过 5 次 → 429
8. 扩展名不在白名单 → 415；文件头（magic）与扩展名不符 → 415
9. 单文件超过 `UPLOAD_MAX_MB` → 413

白名单：`.pdf .png .jpg .jpeg .webp .md .zip`。同内容文件按 sha256 复用，不重复占磁盘。

中文标题在 cmd 里同样可能变问号（`-F` 走的是本地代码页）。要么先 `chcp 65001`，要么在 git-bash / PowerShell 里发这条请求。

### 6.3 审核通过，看它出现在 /library

```bat
curl -X POST http://127.0.0.1:8001/api/review/uploads/7/decide ^
  -H "Content-Type: application/json" ^
  -H "X-Reviewer: uc00001" ^
  -d "{\"action\":\"approve\",\"note\":\"内容没问题\"}"
```

返回里带 `library_id`。然后：

```bat
curl "http://127.0.0.1:8001/api/library?kind=work"
```

就能看到这条；网页 `/library` 是同一份数据。退回则把 `action` 改成 `reject`，`note` 必填（不写理由会 400）。

### 6.4 审核问答条目

问答条目走另一个接口，多一个 `version`（乐观锁）：

```bat
curl -X POST http://127.0.0.1:8001/api/review/item/12/decide ^
  -H "Content-Type: application/json" ^
  -H "X-Reviewer: uc00001" ^
  -d "{\"action\":\"approve\",\"version\":3,\"note\":\"已核对\"}"
```

- `action` 支持 `approve` / `reject` / `edit` / `archive`。
- `version` 对不上返回 409，提示「这条已被别人改过」，防止两个人互相覆盖。
- 通过后后端会 `reload_kb()` 重建检索索引，**立刻**能搜到；不 reload 的话新条目搜不到、归档的还在答。
- **下架资料库条目不要用这个接口**，用 `/api/review/library/{id}/archive`。`/api/review/item/{id}/decide` 操作的是问答库，id 撞上会误伤同号的 `kb_item`。

## 7. 测试体系

### 7.1 分两类

- **脚本级**（`scripts/`）：给你手动跑的检查，输出人看得懂。
- **回归级**（`tests/`）：断言脚本，`[PASS]` / `[FAIL]` 逐条打印，结尾一行 `N pass / M fail / N+M total`。

所有 `tests/*.py` 都是直连 HTTP 的真实请求，不打桩。

### 7.2 逐个说明

| 脚本 | 测什么 | 前置 |
|---|---|---|
| `scripts/smoke.py` | 端到端 25 项：六个页面、三类提问（资料题/寒暄/已知缺口）、投稿开关、资料库、后台、审批、DDL | 服务在 8001 |
| `scripts/selftest.py` | 12 条基础断言（问答链路、引用、兜底） | 服务在 8001 |
| `scripts/eval_set.py` | 30 条评测基线，锁检索与版本字段 | 服务在 8001；`SCRAPE_BYPASS` |
| `tests/test_upload.py` | 投稿：邀请码、授权、电邮、类型白名单、超限、去重、限流、候选入库 | `UPLOAD_CODE` |
| `tests/test_library.py` | 候选 → 通过/退回 → 资料库；邮箱公开开关；待审列表流转 | `UPLOAD_CODE`、`REVIEWERS` |
| `tests/test_public.py` | 公开接口：列表、筛选、单条、统一检索、隐私、404 | 有已上架数据 |
| `tests/test_files.py` | 文件检索、下载、单条、404 | 有已上架且带文件的数据 |

| `tests/test_mcp_files.py` | stdio 拉起 `mcp_files_server.py`，三个工具 | 有文件数据 |

| `tests/test_schema.py` | 新库 DDL（表与视图） | 无 |

### 7.3 跑之前必须知道的三件事

1. **服务要连着**。除 `test_schema` 外，全部打 `http://127.0.0.1:8001`，可以用 `BASE=` 覆盖。
2. **每个请求要带唯一 IP/设备号**。脚本自带 `X-Forwarded-For` + `X-Device-Id`，手写 curl 连打几十次会被 60/小时 的 IP 闸门打成 429。
3. **断言前要过繁简**。脚本里用 OpenCC `t2s` 再比字符串，因为「禁煙」≠「吸烟」、「不能养」≠「不允许」。你写自己的测试也照这个来，否则误报。

### 7.4 实测结果与文档不一致的地方

- `docs/MCP-接入.md` 写 `test_mcp` 应输出 `8 pass`，现在实际是 **9 项**（多了一条「五个工具都注册了」）。
- `docs/反扒.md` 写 `test_scrape` 期望 `7 pass`，现在实际是 **9 项**。
- `test_mcp_files` 是 6 项。我在一个只有单字符文件名的库上跑出 5 pass / 1 fail：它拿最近文件的**前两个字**去搜，文件名是 `x.md` 时搜的是 `x.`，自然搜不到。换成正常文件名就 6/0。这是数据相关，不是接口坏了。
- `eval_set` 的 30 条是按作者真实库写的。我在当前库上实测：不加 `--ask-none` 是 27/30，加 `--ask-none`（`check.bat` 的用法）是 29/30，失败的是「冷氣壞了找誰」——资料库里有内容被搜到，判成「不该命中」。**刚 seed 完的示例库跑这个会大面积失败**，别拿它当安装成功判据；装好没装好，看 `smoke`。

以脚本结尾的 `N pass / 0 fail` 为准。

## 8. MCP

### 8.1 两套部署形态

| 文件 | 形态 | 用途 |
|---|---|---|
| `mcp_server.py` | stdio | 本机客户端（Claude Desktop、Cursor、Hermes）直接拉起进程 |
| `mcp_http.py` | Streamable HTTP（默认 8092） | 给公网用；线上由 `rc-ai-mcp` 单元跑 |
| `mcp_files_server.py` | stdio | 文件查询，三个工具 |
| `mcp_files_http.py` | Streamable HTTP（默认 8093） | 公网 `/ai/mcp-files` |

工具定义只在 `mcp_server.py` / `mcp_files_server.py` 里写一份，HTTP 版直接 `from mcp_server import mcp`，两处不会漂移。

### 8.2 八个工具

`cklc`（五个）：

| 工具 | 参数 | 作用 |
|---|---|---|
| `search_kb` | `query`, `kind`, `limit` | 搜问答 + 资料库，返回带 `type` 的列表 |
| `get_item` | `item_id`, `type` | 按编号取一条；`type=qa` 取问答，`work/link/doc` 取资料库 |
| `search_clauses` | `query`, `limit` | 条款全文检索（FTS5），返回条款号与原文 |
| `get_clause` | `anchor`, `version` | 按条款号取原文，如 `anchor=3.2` |
| `list_updates` | `since` | 自某日起新增/更新的内容 |

`cklc-files`（三个）：

| 工具 | 参数 | 作用 |
|---|---|---|
| `search_files` | `query`, `kind`, `limit` | 按文件名/条目名/说明搜 |
| `get_file` | `file_id` | 文件名、大小、所属条目、下载地址 |
| `list_files` | `kind`, `limit` | 最近上架的文件 |

**参数名坑**：取单条是 `item_id`，不是 `id`；写 `id` 会报参数校验错误。

### 8.3 本机 stdio 注册

Claude Desktop：编辑 `%APPDATA%\Claude\claude_desktop_config.json`

```json
{
  "mcpServers": {
    "cklc": {
      "command": "D:\\Projects\\rc-ai-assistant\\.venv\\Scripts\\python.exe",
      "args": ["D:\\Projects\\rc-ai-assistant\\mcp_server.py"],
      "env": { "RC_AI_BASE": "http://127.0.0.1:8001" }
    }
  }
}
```

改完要**完全退出** Claude（托盘也退），再打开；对话框的工具图标里应看到五个工具。

Cursor：`~/.cursor/mcp.json` 同结构，或在 Settings → MCP → Add new MCP server 里填同样的命令。

Hermes（`--args` 必须放最后）：

```bash
hermes mcp add cklc-local --command "D:\Projects\rc-ai-assistant\.venv\Scripts\python.exe" --env RC_AI_BASE=http://127.0.0.1:8001 --args "D:\Projects\rc-ai-assistant\mcp_server.py"
```

Hermes 连公网 HTTP 更省事：

```bash
hermes mcp add cklc --url http://<服务器IP>/ai/mcp
```

dsh：

```bash

```

（dsh 自身有 MCP 注册竞态，`dsh mcp list` 能看到 `[on] cklc` 但会话里拿不到工具，是它的问题，不是服务端。）

### 8.4 公网端点

```
http://<服务器IP>/ai/mcp          ← cklc，五工具
http://<服务器IP>/ai/mcp-files    ← cklc-files，三工具
```

传输方式是 **Streamable HTTP**，不是 SSE，也不是 stdio。Cherry Studio 里选「Streamable HTTP」并填 URL；Claude Desktop 不认 HTTP，用 `mcp-remote` 转一层：

```json
{
  "mcpServers": {
    "cklc": { "command": "npx", "args": ["-y", "mcp-remote", "http://<服务器IP>/ai/mcp"] }
  }

```

### 8.5 MCP 服务端的环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `RC_AI_BASE` | `http://127.0.0.1:8001` | 后端 API 根；stdio 版靠它知道去哪取数 |
| `MCP_HOST` | `127.0.0.1` | HTTP 版监听地址 |

| `MCP_PUBLIC_HOST` | 空 | 公网 Host 白名单，反代必填，否则 421 |
| `MCP_PUBLIC_BASE` | 同 `RC_AI_BASE` | 只影响返回给用户的下载地址前缀（文件服务用） |

## 9. 部署到服务器

下面的主机、路径、单元名按作者这台写（`159.75.225.125`、`/opt/rc-ai`、`rc-ai` / `rc-ai-mcp` / `rc-ai-mcp-files`）。换成你自己的就是同名替换。

### 9.1 服务器要什么

- Linux（CentOS/RHEL 系实测，systemd + 系统 Apache）
- Python 3.11+
- 目录 `/opt/rc-ai`，里面自带 `.venv`
- 三个 systemd 单元、Apache 反代

### 9.2 第一次手工搭

```bash
ssh root@<服务器IP>
mkdir -p /opt/rc-ai && cd /opt/rc-ai
```

第一次部署要把 `app/ data/ scripts/ mcp_server.py mcp_http.py mcp_files_server.py mcp_files_http.py ask.py requirements.txt .env` 一起传上去；**不要传 `.venv`**（本机的是 Windows 版，服务器用不了）。之后更新代码只走 `deploy.py`，它会刻意跳过 `data/` 和 `.env`，不会覆盖服务器上的库。

```bash
python3 -m venv .venv
.venv/bin/pip install -U pip -i https://pypi.tuna.tsinghua.edu.cn/simple
.venv/bin/pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
mkdir -p data
```

### 9.3 三个 systemd 单元

仓库里没有 `.service` 文件，下面是线上在用的结构，按需新建 `/etc/systemd/system/rc-ai.service`：

```ini
[Unit]
Description=RC AI assistant (uvicorn)
After=network.target

[Service]
WorkingDirectory=/opt/rc-ai
ExecStart=/opt/rc-ai/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8091
Restart=always
RestartSec=2
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=multi-user.target
```

`rc-ai-mcp.service`（`[Unit]` / `[Install]` 段与上面相同，这里只列 `[Service]`）：

```ini
[Service]
WorkingDirectory=/opt/rc-ai
Environment=RC_AI_BASE=http://127.0.0.1:8091
Environment=MCP_PORT=8092
Environment=MCP_PUBLIC_HOST=<服务器IP>
ExecStart=/opt/rc-ai/.venv/bin/python /opt/rc-ai/mcp_http.py
Restart=always
```

`rc-ai-mcp-files.service` 同结构，改三处（`[Unit]` / `[Install]` 段与第一个单元相同，这里只列 `[Service]`）：

```ini
Environment=RC_AI_BASE=http://127.0.0.1:8091
Environment=MCP_PORT=8093
Environment=MCP_PUBLIC_HOST=<服务器IP>
Environment=MCP_PUBLIC_BASE=http://<服务器IP>/ai
ExecStart=/opt/rc-ai/.venv/bin/python /opt/rc-ai/mcp_files_http.py
```

启用：

```bash
systemctl daemon-reload
systemctl enable --now rc-ai rc-ai-mcp rc-ai-mcp-files
systemctl is-active rc-ai rc-ai-mcp rc-ai-mcp-files
```

三个都应是 `active`。

### 9.4 Apache 反代（有顺序坑）

反代写在 `/etc/httpd/conf.d/bike.conf`（这台机器上 BIKE 站也在这个文件里，只加 `/ai` 前缀，不碰别的）：

```apache
ProxyPass        /ai/mcp-files http://127.0.0.1:8093/mcp
ProxyPassReverse /ai/mcp-files http://127.0.0.1:8093/mcp
ProxyPass        /ai/mcp       http://127.0.0.1:8092/mcp
ProxyPassReverse /ai/mcp       http://127.0.0.1:8092/mcp
ProxyPass        /ai/          http://127.0.0.1:8091/
ProxyPassReverse /ai/          http://127.0.0.1:8091/
```

**顺序坑**：Apache 的 `ProxyPass` 按**出现顺序**匹配，不是最长前缀优先。`/ai/mcp-files` 必须写在 `/ai/mcp` 前面，否则会被 `/ai/mcp` 抢走，文件服务永远 404。

改完：

```bash
httpd -t && systemctl reload httpd
```

用 `reload` 不用 `restart`——restart 会掐断同机其他站。

### 9.5 用 deploy.py 发版

日常改完代码：

```bat
.venv\Scripts\python.exe scripts\deploy.py --dry-run
.venv\Scripts\python.exe scripts\deploy.py
```

它做的事（对应 `scripts/deploy.py` 的代码）：

1. 检查密钥 `~/.ssh/rc_ai_deploy` 在不在，不在直接退出。
2. 打包这些：`app/ scripts/ tests/ docs/ mcp_server.py mcp_files_server.py mcp_http.py mcp_files_http.py ask.py requirements.txt`，排除 `__pycache__` 和 `.pyc`。
3. `scp` 到 `/opt/rc-ai/_deploy.tar.gz`。
4. 服务器上先备份现有 `app/` 与 `mcp_server.py` 到 `backups/code-<时间>.tar.gz`；**备份失败就不覆盖**。
5. 解包覆盖。
6. `.venv/bin/pip install -q -r requirements.txt`。
7. `systemctl restart rc-ai`，然后最多等 20 秒轮询 `is-active`；失败会打 `journalctl -u rc-ai -n 15`。
8. 在服务器上验证三项：`127.0.0.1:8091/health`、`/api/library?kind=work`、`/library` 的 HTTP 码。
9. 全过打印「部署完成」，否则「有检查没过，看上面的输出」。

四个必须知道的限制：

- **不传 `data/` 和 `.env`**。服务器上的库和密钥不会被本地覆盖，这是好事；但意味着改 `.env` 要手动上服务器改。
- **只重启 `rc-ai`**。改了 `mcp_*.py` 之后要自己补一句：
  ```bash
  ssh -i ~/.ssh/rc_ai_deploy root@<服务器IP> "systemctl restart rc-ai-mcp rc-ai-mcp-files"
  ```
- 验证只打 `127.0.0.1:8091`，不证明公网通。发完再打一次外网：
  ```bash
  curl http://<服务器IP>/ai/health
  ```
- `--dry-run` 只在本机打包并打印步骤，不连服务器。

可用环境变量覆盖目标：`DEPLOY_HOST`、`DEPLOY_USER`、`DEPLOY_PATH`、`DEPLOY_KEY`。

### 9.6 MCP 的 421 坑

MCP Python SDK 默认只放行 `localhost` 的 Host。走 Apache 反代后，Host 头是公网 IP，SDK 在进入业务逻辑前就会回 **421 Misdirected Request**，客户端只看到「连不上」，服务端日志里线索很少。

`mcp_http.py` 已经处理：读 `MCP_PUBLIC_HOST`，拼进 `TransportSecuritySettings.allowed_hosts`：

```python
allowed = ["127.0.0.1:*", "localhost:*", "[::1]:*"]
if PUBLIC_HOST:
    allowed += [PUBLIC_HOST, f"{PUBLIC_HOST}:*"]
```

两种写法都要有——Host 头有时带端口有时不带。所以 `MCP_PUBLIC_HOST` 必须设，不设就是 421。

### 9.7 端口三层，缺一层就连不上

1. 腾讯云 Lighthouse 控制台防火墙放行（8091/8092/8093，或只放 80 走反代）
2. 主机 firewalld：
   ```bash
   firewall-cmd --permanent --add-port=8091/tcp
   firewall-cmd --reload
   ```
   只走 Apache 反代的话，8092 / 8093 不必对外开放（它们监听 `127.0.0.1`，Apache 在本机转发）。
3. 程序真的在听：`ss -lntp | grep 809`

症状都是「连不上」，但查的顺序要按这个来。

### 9.8 上线前检查清单

- [ ] `.env` 里 `REVIEWERS` 已填真实审核人学号（留空 = 谁都能批）
- [ ] `UPLOAD_CODE` 不是默认值，也不要是 `123456`
- [ ] `MCP_PUBLIC_HOST` 两个 MCP 单元都设了
- [ ] `httpd -t` 通过，`systemctl reload httpd` 后 BIKE 站正常
- [ ] `curl http://<服务器IP>/ai/health` 返回 `ok:true`
- [ ] `curl http://<服务器IP>/ai/api/search?q=寵物` 有结果
- [ ] `.env` 权限 600：`chmod 600 /opt/rc-ai/.env`

## 10. 出问题怎么查

| 症状 | 先查什么 | 处理 |
|---|---|---|
| 起服务报 10048 | `netstat -ano` 里查 `:8001` | 杀掉占用进程，或换端口 |
| 打开页面 500，日志 `ModuleNotFoundError` | 日志里的包名 | 用 `.venv\Scripts\python.exe -m pip install <包>`；常见是 `pymupdf`（requirements 没列） |
| `/health` 显示 `extractive` | `.env` 的 `LLM_BASE` / `LLM_KEY` | 两项都要非空；检查是否有引号、是否有系统环境变量覆盖 |
| 提问 429，提示「这个小时已经用完」 | `quota.llm_left` | 等下一个小时，或调 `ASK_LIMIT_PER_HOUR`；测试时换 `X-Student-Id` |
| 提问 429，「请求太频繁，请一分钟后再试」 | 是不是连打了公开接口 | 等 60 秒；内部脚本带 `X-Scrape-Token: <SCRAPE_BYPASS>` |
| 搜不到刚导入的条目 | `status` 是不是 `published`；繁简 | `/api/stats` 看 `loaded_for_search`；审批通过要 `reload_kb`（接口会自动做） |
| 条款 uid 是空的 | 导入后有没有重启 | 重启服务，`init_db()` 会回填 |
| 上传 503 | `UPLOAD_CODE` 是否为空 | 填上并重启 |
| 上传 413 / 415 | `UPLOAD_MAX_MB`；扩展名与文件头 | 改配置；检查是不是把 zip 改名成 pdf |
| `/review` 一直 401 | 页面顶部没填学号，或填的号不在 `REVIEWERS` | 填对的号；改 `REVIEWERS` 后重启 |
| 保存条目 409 | 别人先改过，`version` 旧了 | 刷新页面再改 |
| 文件 404 | `data/files` 有没有一起部署；`/files` 挂载是否正常 | 传文件目录；确认没有把 `data/` 覆盖成空 |
| MCP 连不上，客户端报 421 | `MCP_PUBLIC_HOST` 没设 | 设上并重启 MCP 单元 |
| MCP 连上了但工具没有 | 客户端 URL、传输方式 | URL 用 `/ai/mcp`（不是 `/ai/mcp/`），传输选 Streamable HTTP；stdio 客户端要指向 `mcp_server.py` |
| MCP 工具报参数错误 | 用了 `id` 而不是 `item_id` | 改参数名 |
| `systemctl restart` 失败 | `journalctl -u rc-ai -n 50 --no-pager` | 九成是依赖缺失或端口占用；`systemctl status` 看退出码 |
| 部署后公网 502 | 本机 8091 通不通；Apache 有没有 reload | `curl 127.0.0.1:8091/health`，再看 `httpd -t` |
| 部署后 BIKE 站坏了 | `bike.conf` 里 `ProxyPass` 顺序/前缀 | `/ai/mcp-files` 必须在 `/ai/mcp` 前；只加 `/ai` 前缀 |
| 中文变问号 | cmd 代码页 | `chcp 65001`；请求体用 UTF-8 文件 + `--data-binary @body.json` |
| `.env` 改了没生效 | 有没有重启；系统环境变量是否同名 | 重启；`set LLM_KEY` 看系统里有没有 |
| 库被误删 | `backups/` 下 `kb-<时间>.sqlite3` | 停服务 → 覆盖回 `data/kb.sqlite3` → 起服务（`start_all.bat` 每次启动都会备份一份） |

日志位置：本机看 `data\server.out` / `data\server.err`（`start_all.bat` 重定向写入）和 `data\server.log`；服务器看 `journalctl -u rc-ai`。审批与用量在 `/admin`，未命中的问题在 `/api/review/gaps`。
