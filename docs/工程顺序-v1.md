## 阶段顺序与理由

### 第 1 阶段：上传页（现在做）

**做什么**：`/upload` 页面 + 文件入库 + 写候选。

- 邀请码进门，表单（类型、标题、作者、说明、同意声明）
- 文件白名单、20MB、IP 限流、改名存储、算哈希
- 提交后给编号，进 `candidate`；发一条通知

**为什么排第一**：它是唯一「没有它，后面全都空转」的环节。没有内容进来，只读接口、MCP、迁移都没有意义。而且它不依赖身份系统，今天就能做。

**完成标准**：你自己传一个 PDF、一张图，后台能看到、能预览、能通过；重复文件不重复存；超限被拒。

### 第 2 阶段：审核端接附件

**做什么**：候选详情页显示附件（图片缩略、PDF 内嵌）、通过后生成作品/资源记录、退回保留 30 天。

**为什么第二**：第 1 阶段只解决「收」，这一阶段解决「收进来之后怎么变成正式内容」。没有它，候选队列会堆着没人处理。

### 第 3 阶段：只读 API（匿名 + 限流）

**做什么**：`search_kb` / `get_item` / `get_clause` / `list_updates` 四个接口，匿名可读，IP 限流，单次 ≤20 条，不提供全量导出。

**为什么第三**：内容先有，接口才有东西可给。而且它不改数据库，风险低。

**注意**：这一步之前不要承诺「对外开放」——公开一个空库或半成品，比不公开更伤。

### 第 4 阶段：迁移到新库（schema v1）

**做什么**：建新表 → 搬 `kb_item`/`chunk` → `legacy_map` → 双写 → 视图兼容 → 切读 → 老表转备份。

**为什么放这么后**：这是唯一会动到线上数据的阶段，风险最高。前三阶段都不依赖它；等接口和上传流程稳定了再迁，回滚成本最低。

**硬门槛**：迁移前后 `smoke` 全绿 + 抽查 10 条问答的引用一致。

### 第 5 阶段：MCP 包装

**做什么**：把四个只读接口包成 MCP，给同学的 AI 客户端用。

**为什么最后**：它是「包装」，不是「能力」。API 稳定之前做 MCP 等于返工。

### 第 6 阶段：上线与身份

- 域名 + HTTPS（外部依赖）
- `whoami` 接书院登录（外部依赖）
- 投稿改为实名，配额按人算

**这一步之前，投稿只能用邀请码，不能用学号。**

## 依赖关系

```
上传页 ──► 审核附件 ──► 只读 API ──► MCP
                │
                └──► 新库迁移（可并行准备，切读放在 API 之后）
                          │
                          └──► 上线（域名/身份，外部依赖）
```

## 每阶段的闸门

| 阶段 | 必须通过 |
|---|---|
| 1 | `smoke 19/19` + 上传专项（白名单/超限/重复/邀请码） |
| 2 | `smoke 19/19` + 审核专项（通过/退回/软删/预览） |
| 3 | `smoke 19/19` + 接口专项（匿名限流、条数上限、无私有字段） |
| 4 | `smoke 19/19` + 迁移对账（条数、抽样引用） |
| 5 | `smoke 19/19` + MCP 四个 tool 各调一次 |

## 可以砍的

- 上传 API（submit key 版）：人等页面够用，机器对接再补
- 全量导出：不做，避免一次被抓走
- 邮件通知：先站内/微信，够用
