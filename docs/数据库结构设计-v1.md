# 书院数据库 · 结构设计 v1

> 目的：把“公文、条目、院生作品、其他资源”放到一个库里，既能给崑崑用，也能给别的项目、同学的 AI 用。
> 状态：设计稿，未动线上库。数值全部来自现有系统（115 条问答 / 368 条条款）。

---

## 一、先定三条原则

1. **一切皆资源，但资源分型**
   同一个搜索框要能查公文、问答、作品、网站；但它们的字段差别很大，不能硬塞进一张表。
   做法：**统一基表 `resource` + 类型子表**，搜索查基表，展示查子表。

2. **原文与解读分开**
   公文原文（条款）只加不改；问答、作品介绍是“解读”，可改、要审核。这条已经验证过，别合并。

3. **任何对外可见的东西都要能回答三个问题**
   - 依据是什么（来源 / 条款 / 作者）
   - 谁批准的、什么时候
   - 什么时候失效 / 该复查了

## 二、实体总览

```
                       ┌──────────────┐
                       │   resource   │  统一基表（id / type / 标题 / 状态 / 可见性）
                       └──────┬───────┘
        ┌──────────────┬──────┴───────┬────────────────┐
        ▼              ▼              ▼                ▼
   ┌─────────┐   ┌──────────┐   ┌──────────┐    ┌──────────┐
   │   doc   │   │    qa    │   │   work   │    │   link   │
   │  公文   │   │  条目    │   │ 院生作品 │    │ 其他资源 │
   └────┬────┘   └────┬─────┘   └────┬─────┘    └────┬─────┘
        │             │              │               │
        ▼             ▼              ▼               ▼
 ┌────────────┐  ┌──────────┐   ┌──────────┐   ┌──────────┐

 └─────┬──────┘  └──────────┘   └──────────┘   └──────────┘
       ▼

   └────────┘

  公共：tag / resource_tag / review_log / change_log / client / api_log
```

## 三、基表 `resource`

所有类型的公共字段。**搜索、权限、审核状态都只看这张表。**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | PK | 统一编号（对外暴露用，不用各子表 id） |
| `type` | enum | `doc` / `qa` / `work` / `link` |
| `title` | text | 显示标题（公文名 / 问题 / 作品名 / 网站名） |
| `summary` | text | 一句话摘要，列表和搜索结果用 |
| `status` | enum | `draft → review → published → deprecated → archived` |
| `visibility` | enum | `public` / `student` / `college` / `admin` |
| `lang` | enum | `zh-Hant` / `zh-Hans` / `en` / `mixed` |
| `owner` | text | 责任人（学号或姓名） |
| `reviewer` | text | 最后批准人 |
| `published_at` | date | 首次发布 |
| `updated_at` | timestamp | 内容最后修改 |
| `review_due` | date | 下次必须复核的日子（到期提醒） |
| `valid_from` / `valid_until` | date | 生效 / 失效（公文用，其他可空） |
| `source_kind` | enum | `official` / `student` / `external` / `unverified` |
| `search_text` | tsvector | 统一检索列（标题+摘要+子表正文，触发器维护） |

> 为什么把 `status` 放基表：学生端只查 `published`，一条 SQL 就能过滤全部类型，不用 union 四张表。

## 四、四种类型各要什么

### 4.1 `doc` 公文

| 字段 | 说明 |
|---|---|
| `doc_no` | 文号（`CKLC/R0001/2020`） |
| `issuer` | 发布机构（书院 / 澳大 / 学生事务） |
| `doc_type` | `regulation` 规章 / `notice` 通知 / `guideline` 指引 / `form` 表格 / `minutes` 会议记录 |
| `version` | 当前有效版本号（指向 `doc_version`） |
| `file_url` | 原件（PDF）在 COS 上的地址 |
| `file_hash` | 文件指纹，防止同名不同版 |

`doc_version`（一份公文可以有多版，旧的不能删）：

| 字段 | 说明 |
|---|---|
| `doc_id` | 属于哪份公文 |
| `version` | `AY2026-2027` / `v3` |
| `issued_at` / `effective_from` / `effective_until` | 发布、生效、废止 |
| `file_url` / `file_hash` | 该版原件 |
| `supersedes` | 被它取代的版本 id（可空） |

`clause`（段落级原文，崑崑引用的就是它）：

| 字段 | 说明 |
|---|---|
| `doc_version_id` | 属于哪一版 |
| `anchor` | 条款号 `3.2` |
| `section` | 章节 `3. Visitors` |
| `variant` | `zh` / `en`（同一条中英各一行） |
| `text` | 正文，一字不改 |
| `sort_key` | 排序用（3.2 < 3.10 这种坑） |

### 4.2 `qa` 条目

| 字段 | 说明 |
|---|---|
| `question` / `answer` | 问题与答案 |
| `ttl_type` | `A` 稳定 / `B` 年度 / `C` 实时 |
| `original_answer` | 导入时的原文（改过之后还能对照） |
| `audience` | `all` / `freshman` / `resident` |
| `category` | 住宿 / 设施 / 规章 / 校务 / 活动 |

`qa_clause`（一条问答可以依据多条条款，这是关键改动）：

| 字段 | 说明 |
|---|---|
| `qa_id` / `clause_id` | 多对多 |
| `strength` | `direct` 直接规定 / `explain` 解释 / `ref` 参考 |
| `note` | 为什么算依据 |

> 现在只能绑一条（`source_chunk_id`），实际会出现“换房要同时看 5.1 和 6.2”的情况。

### 4.3 `work` 院生作品

| 字段 | 说明 |
|---|---|
| `author_id` / `author_name` | 学号 + 显示名（是否公开由作者选） |
| `work_type` | `skill`（给 AI 用的技能）/ `tool`（小工具）/ `app` / `art` / `paper` / `dataset` |
| `summary` | 一句话讲清它解决什么问题 |
| `usage` | 怎么用（命令 / 链接 / 步骤） |
| `repo_url` / `demo_url` | 仓库与演示地址 |
| `license` | `MIT` / `GPL-3.0` / `CC-BY` / `all-rights` |
| `tech` | 技术标签（Python / 前端 / 硬件…） |
| `cover_url` | 截图或封面 |
| `consent` | 作者是否同意公开（`yes` / `anon` / `no`） |
| `contact` | 想被联系时的联系方式（可空） |

`work_file`：附件（截图、说明 PDF、二进制）。

**三条硬规矩**：
- 没拿到作者 `consent=yes`，不上公开列表
- 作品是作者版权，不随系统许可；页面上必须写清
- 作者毕业/要求下架时，`status=archived`，链接保留但标注“已下架”，不物理删除

### 4.4 `link` 其他资源

| 字段 | 说明 |
|---|---|
| `url` / `title` | 地址与名称 |
| `link_type` | `official` 官网 / `student` 学生自建 / `tool` 工具 / `club` 社团 / `doc` 外部文档 |
| `is_official` | 布尔；false 时前端必须加“非官方”标记 |
| `lang` / `region` | 语言 / 面向哪个校区或群体 |
| `description` | 一句话说明 |
| `recommended_by` | 谁推荐（学生推荐要留名） |
| `risk` | `none` / `login-required` / `ads` / `unofficial` / `dead` |

`link_check`（网站会死，必须定期探活）：

| 字段 | 说明 |
|---|---|
| `link_id` / `checked_at` | 哪条、什么时候查的 |
| `http_status` | 200 / 404 / 超时 |
| `final_url` | 跳转后的真实地址 |
| `note` | 例如“已改域名”“需登录” |

## 五、公共表

| 表 | 作用 |
|---|---|
| `tag` / `resource_tag` | 跨类型标签（住宿、设施、AI、开源…），搜索和导航靠它 |
| `review_log` | 谁、何时、对哪条、做了什么（approve / reject / bind / archive），带 before/after |
| `change_log` | 内容级 diff（哪一段改了），审计和“这条什么时候变的”用 |
| `client` | 调用方：名称、类型（内部/学生/外部）、key、scope、限流 |
| `api_log` | 对外每次调用：谁、问什么、返回哪些 id、耗时 |
| `glossary` | 术语（HA、RC、High Table），条目可以指向它 |

## 六、状态与权限

**状态机**（四类共用）：

```
draft ──► review ──► published ──► deprecated ──► archived
  ▲          │            │
  └── 退回 ──┘            └── 到期自动转 deprecated（有 valid_until 时）
```

**可见性**：

| visibility | 谁能看 |
|---|---|
| `public` | 所有人（含未登录） |
| `student` | 有学号的人（将来接登录态） |
| `college` | 书院内部（审核人、老师） |
| `admin` | 仅管理员 |

对外 API 默认只返回 `published` + `public`；`student` 级别需要调用方带身份。

## 七、搜索怎么做

- 一个入口：`GET /api/db/search?q=...&type=doc,qa,work,link`
- 底层：`resource.search_text`（tsvector）+ 类型过滤；中文用 `pg_jieba`/`zhparser`
- 返回统一结构：`id / type / title / summary / 命中片段 / 依据（条款号或作者）/ 状态`
- **不合并排名**：公文和作品的相关性不可比，先按类型分组返回，前端分栏展示

---

## 八、对外接口（只读四个）

| 接口 | 用途 |
|---|---|
| `search_kb(q, type?, limit)` | 统一搜索，返回 id + 摘要 + 依据 |
| `get_item(id)` | 取一条完整内容（按类型返回不同字段） |
| `get_clause(doc_no, version, anchor)` | 取条款原文（给“我要看原文”用） |
| `list_updates(since)` | 自某日起新增/修改/废止了什么 |

MCP 就是把上面四个包成四个 tool，不另做一套。

## 九、和现有库怎么接

现在：`kb_item`（115 条）+ `chunk`（368 条）+ 6 张表。

迁移顺序（**每一步都可停**）：

1. **建新表**（`resource / doc / doc_version / clause / qa / qa_clause / work / link`），不动老表
2. **搬数据**：`chunk → clause`（补 `doc_version`），`kb_item → qa`（保留 id 映射表 `legacy_map`）
3. **双写**：新代码写新表，老接口读视图 `v_qa`（由新表拼出老结构），崑崑不用改
4. **切读**：确认一致后，崑崑改读新表
5. **停老表**：`kb_item / chunk` 转为历史备份，不删

> 迁移期间 `legacy_map(old_id, new_id, type)` 是保命的，别省。

## 十、现在就能定的、和要你拍板的

**我已按“稳”的方向定了**：
- 基表 + 子表，不用大 JSON 字段
- 条款级原文独立，问答绑多条
- 作品必须有作者同意、可下架不删
- 外部链接必须有“是否官方”和定期探活

**要你拍板的三件**：

1. **院生作品的作者信息公开到什么程度？** 默认显示“作者 + 年级”，还是允许匿名？毕业后的作品留不留？
2. **“其他资源”谁可以推荐？** 只有审核人，还是任何学生都能提、审核后上线？
3. **对外 API 第一批给谁？** 只给你自己的机器人，还是先放一两个同学试用？
