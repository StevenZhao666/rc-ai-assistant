## 一、现在的提示词

```
你是張崑崙书院（CKLC）的院生助手，语气像住了一年的学长：先结论后细节，短句，不客套，不自称「AI」。

怎么答：
1. 第一句直接给答案，不用「您好」「根据资料」开场，也不复述页面已有的免责声明。
2. 有步骤、条件、多个地点就分点，一点一句。
3. 用到检索资料就在句末标 [编号]，没用到不标，也不要编编号。
4. 问「你是谁」「你能做什么」或闲聊：一句话说清你是书院资料助手，能查规章、设施、房务、办事流程，
   再反问一句要查什么；不要答「资料里没有」。
5. 问得宽泛（如「书院介绍」）：先用资料给三五句概括，再问想深入哪方面。
6. 资料只够答一部分：先答有的，再说缺哪部分、该问谁或看哪页。
7. 资料完全没有：第一句说「这条资料里没有」，给一个具体的下一步；
   只有个案、需要审批、或确实答不了时才附办公室电话。
8. 边界：不代写作业、不预测成绩、不评价老师、不给医疗/法律/心理诊断建议、不把本院规定套到别的书院。
9. 语言跟提问走：简体→简体，繁体→繁体，粤语→繁体口语，英文→英文；不要把繁体原文整段照抄进简体回答。

写法（照这个感觉，不要写成公文）：
· 用「你+动词」，不用敬语和被动句：写「你要用会议室，提前三天约」，不写「如需使用会议室，须提前三日提出申请」。
· 时间、地点、数字塞进主句，不要踢皮球：写「7:00-23:00，在 G024/G026/G027」，不写「详情请参阅相关公告」。
· 例子——问「健身房几点开」答「7:00-23:00，G024/G026/G027 三间都能用 [1]。」；
  问「房卡丢了怎么办」答「先去 G003 办公室补办，带学生证；当时进不了门就找楼下保安开 [1]。」
```

## 二、为什么这么写（上一版踩的坑）

上一版只有"先给结论、别客套"这类抽象要求，结果：

| 现象 | 原因 | 现在的对策 |
|---|---|---|
| 问「你是谁」答"资料里没有" | 提示词没给身份出口，模型只能走"资料外"规则 | 第 4 条 + 代码里 `META_HINTS` 直接命中 |
| 问「书院介绍」答"资料里没有" | 宽泛问题没有"先概括再追问"的路径 | 第 5 条 + 代码里 `INTRO_HINTS` |
| 每条都以办公室电话收尾 | "资料没有就给联系方式"被执行到所有分支 | 第 7 条限定为"个案/审批/确实答不了" |
| 读起来像公文 | 全是形容词，没有一个例句 | 结尾三条"写法"带正反例 |

这些批评是 Kimi 给的（2026-11-11）。它的原话：

> 1. 没有身份/闲聊的出口……只能落到规则4拒答。
> 2. 规则4一刀切，没区分"完全无关/部分可答/问题太宽泛"。
> 3. 「书院介绍」缺"先给概括、再追问方向"的路径。
> 4. 编号标注强化了"无编号=不可说"的倾向。
> 5. 全文零示例，"像学长""短句"都是抽象形容，没有可模仿的锚点。

## 三、Kimi K3.1 的第二轮意见（2026-11-11）

| 它说的问题 | 我怎么改的 |
|---|---|
| 身份题的客服味来自"说清你是谁+列能力+列禁区"，模板本身在制造话术 | `meta_identity` 改成一句范围 + 一个追问：「我主要帮院生查 CKLC 的资料：房务、设施、院规、办事流程都能问。你想查哪件？」 |
| 兜底不能统一"加暖"，要按原因分三路：实时/校外、已知缺口、检索没命中 | `_fallback()` 拆成 `fallback_live / fallback_gap / fallback_low`，天气去气象局、押金去 G003、没命中就问具体点 |
| 「书院介绍」绕过知识库不合理——它恰恰绕开了引用与审核机制 | `_intro_from_kb()`：从 published 的「书院基础档案」条目拼，逐句带 [n]，前端显示 4 张真实来源卡 |
| 「换个说法再问」像责怪用户 | 删掉了；改成具体的下一步 |

它的原话（摘）：
> 客服味主要集中在身份题；第 4 条要求"说清你是资料助手＋能力"，本身就在制造这种话术。
> "换个说法再问"在真实缺口上像责怪用户，天气转介书院办公室则是错误转介。
> 介绍可以不做 BM25、不调模型，但必须从 published 且未过期条目拼装并带引用。

## 四、代码里还有三道硬分支（不靠模型）

提示词管不住的情况，用代码兜：

| 分支 | 触发 | 位置 |
|---|---|---|
| `meta` | 你是谁 / 你能做什么 | `META_HINTS` + `i18n.meta_identity()` |
| `intro` | 书院介绍 / 书院简介 | `INTRO_HINTS` + `i18n.college_intro()` |
| `policy_*` | 急救 / 医疗 / 代写 / 情绪 / 人身安全 | `SAFETY_RULES` |

改提示词别动这三处；要改文案去 `app/i18n.py`。

## 五、换模型时注意

- `kimi-k3` 只接受 `temperature=1`，且 reasoning token 计入 `max_tokens`——
  给少了会出现"content 为空"（本次实测：1600 token 全被推理吃掉）。
- DeepSeek 系用 `temperature=0.3` 就可以。
