# 内容版本与引用契约（草案）

Kimi 的建议里最值得现在做的一条：**让每条内容都能复现「当时依据哪一版」**。不做这个，以后合库、换模型、接客户端、处理纠错投诉，都要重洗历史。

## 一、加什么字段

三张表统一加：

| 字段 | 类型 | 含义 |
|---|---|---|
| `uid` | TEXT | 稳定 ID，永不变（`kb-0009`、`chunk-0731`），对外只认它 |
| `revision` | INTEGER | 第几版，每次内容变更 +1 |
| `content_hash` | TEXT | 正文的 sha1 前 12 位，判断“内容真的变了没” |
| `effective_from` | TEXT | 从哪天起有效（可为空 = 立即） |
| `effective_to` | TEXT | 到哪天失效（可为空 = 长期） |
| `supersedes` | TEXT | 被哪一版取代（uid + revision） |

已有的 `status`、`version`（学年）、`source`、`verified_at`、审核记录继续用。

## 二、什么时候写

| 时机 | 动作 |
|---|---|
| 新建条目 | `uid` 生成，`revision=1`，`content_hash=sha1(正文)` |
| 编辑已发布条目 | `revision+1`，重算 hash；旧版留在 `kb_revision` 历史表 |
| 审核通过 | 写 `reviewed_by`、`reviewed_at`，状态转 `published` |
| 条款重新导入 | 同一 `source+version+anchor` 覆盖时 `revision+1`，旧版进历史表 |

`content_hash` 没变就不加 revision（避免“改了个错别字算新版”）。

## 三、回答里怎么体现

现在引用长这样：

```json
{"id": 9, "question": "張崑崙書院允許寵物嗎？"}
```

改成：

```json
{"uid": "kb-0009", "revision": 3, "content_hash": "a1b2c3d4e5f6",
 "effective_from": "2026-08-01", "question": "…"}
```

前端不用全展示，折叠区里显示一行：`v3 · 2026-08-01 起生效 · a1b2c3`。学生申诉时能对上号。

## 四、历史表

```sql
CREATE TABLE kb_revision (
  uid TEXT, revision INTEGER, content_hash TEXT,
  question TEXT, answer TEXT, status TEXT,
  changed_by TEXT, changed_at TEXT, note TEXT,
  PRIMARY KEY (uid, revision)
);
```

条款同理：`chunk_revision`。

## 五、合同（对外承诺）

三句话，写进 MCP 工具说明和 API 文档：

1. 只返回 `status='published'` 且 `effective_from <= 今天 <= effective_to（或空）` 的版本
2. 同一个 `uid` 只返回最新 `revision`
3. 引用里必须带 `uid + revision`，缺一不可

## 六、评测题（锁行为）

30–50 条，覆盖四类，跑一次 5 分钟：

| 类型 | 例子 | 期望 |
|---|---|---|
| 正常 | 书院能不能养宠物 | 命中 kb-0009，带 uid+revision |
| 过期 | 去年的活动截止日期 | 不返回 expired 版本 |
| 无答案 | 明天会不会下雨 | 明说查不到，不给编号 |
| 跨来源 | 洗衣房时间（问答 + 条款都有） | 两个来源都返回，各自带 uid |

先写 30 条，跑通再扩。**这套题就是以后换模型/换检索的回归基线。**

## 七、迁移步骤（一次做完，约半天）

1. 加字段 + 历史表（`_migrate()` 里幂等执行）
2. 回填：`uid` 按 `kb-{id:04d}` / `chunk-{id:04d}`，`revision=1`，`content_hash` 现算
3. 发布/编辑路径写新字段 + 写历史表
4. 引用输出加三个字段（前端折叠区显示一行）
5. 30 条评测题跑通，进 `check.bat`

## 八、不做的事

- 不做跨库 SQL VIEW（Kimi 说得对：两个 SQLite 文件别指望视图，应用层拼）
- 不做全量历史（只留最近 5 版，更早的归档到冷表）
- 不把完整提问长期存起来（审计只记 uid + revision + 时间）
