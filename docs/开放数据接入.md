# 开放数据接入（data.um.edu.mo）

> 2026-11-11　配套脚本：`scripts/fetch_open_data.py`

---

## 一、这个平台是什么

**不是大模型 API，是学校的数据开放平台**（Azure API Management + OneDrive，ICTO 运营）。免费，但需要授权。

| 类别 | 数据集 | 对我们 |
|---|---|---|
| **Academic** | **Courses**（课程 + section + 上课时间 + 教师）、**Course Catalog**（本学年全部课程） | ⭐ 补上"这门课是什么/什么时候上/谁教"，绕开 SIWEB 人工登录 |
| About UM | Organizational Units、**Public Holidays** | 校历、假期（B 类年度的基础） |
| Facilities | Sports Facilities、Sports Facilities Booking | 设施清单与预约 |
| Media | **Events**、**News** | 活动/新闻（C 类只给链接的来源） |
| ⚠️ 敏感 | Wifi Access Log、Access Control Records、Student Meal Consumption、Power Consumption | **不要用**：个人位置/门禁/消费，属 PDPA 高风险 |

**结论：它解决"内容从哪来"，不解决"模型从哪来"。**

---

## 二、申请（四步，官方 Quick Start）

1. ICTO 账号页 → **Manage Account** → 在 `NOT APPLY` 里找 **OPEN DATA API PLATFORM** → 点申请
2. 等最多 **1 小时**生效
3. `data.um.edu.mo` → **Sign in with UMPASS** → Microsoft 登录页填 `学号@um.edu.mo` → 回 UMPASS 输密码
4. **Products** → `UM Members` → 建一个 production subscription → 拿到 **API key**

密钥写进项目 `.env`：

```
OPEN_DATA_KEY=把密钥粘在这里
```

## 三、脚本怎么用

```bash
# 1. 看配置了哪些数据集（不需要密钥）
.venv\Scripts\python.exe scripts\fetch_open_data.py --list

# 2. 探接口通不通（需要密钥；会打印 HTTP 码和记录数）
.venv\Scripts\python.exe scripts\fetch_open_data.py --check

# 3. 拉一个数据集，写进草稿箱
.venv\Scripts\python.exe scripts\fetch_open_data.py --fetch catalog

# 4. 没有网络/密钥时，用本地 JSON 验证解析
.venv\Scripts\python.exe scripts\fetch_open_data.py --ingest tests\sample_courses.json --dataset catalog --dry-run
```

已实测：

```
密钥 = 未配置
  courses      /api/courses             课程与课堂安排（Courses）
  catalog      /api/coursecatalog       课程目录（Course Catalog）
  ...

catalog: 从 tests/sample_courses.json 解析 3 条 → 已写入草稿
chunk 表： 3 条  ('[catalog] CISC1001', 'draft', ...)
检索是否包含草稿： False
```

## 四、唯一待填的东西：接口路径

门户的 **APIs** 页（登录后可见）会给出每个数据集的真实路径。拿到后改 `scripts/fetch_open_data.py` 顶部的 `DATASETS`：

```python
"catalog": {
    "path": "/api/coursecatalog",   # ← 换成门户里的实际 Path
    "params": {},
    "title_field": "courseCode",
},
```

脚本对返回结构做了兼容：裸数组、`{value:[...]}`、`{data:[...]}`、`{items:[...]}` 都能解析。如果门户用的是别的包装字段，改 `as_records()` 里的列表即可。

## 五、三条边界（写进代码，不靠自觉）

1. **拉下来的东西只能是草稿**（`chunk.status='draft'`），不进检索。实测确认：草稿写进去后，`published_items()` 里查不到
2. **同一标题重复拉取会先删旧草稿**，不会越堆越多
3. **敏感数据集不接**：WiFi 日志、门禁记录、饭卡消费——这三类即使有权限也不碰

|---|---|---|
